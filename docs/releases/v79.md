# Perdana Island GNOME v79

Targets GNOME Shell 50 and 51. Published as the `v79` tag and the
`Perdana-Island-GNOME-v79.shell-extension.zip` archive. The Plasma widget
remains on v76.

## Highlights

- **Messages page reworked.** Chat notifications are grouped into one card per
  conversation (app → sender → messages). Expand a card to read every message
  in order; the header shows the latest preview only while collapsed.
- **Multiple messages are no longer lost.** A chat app that reuses one
  notification object for each new message now produces a separate history row.
  Each message has its own identifier and unread state.
- **Popup keeps a burst.** A WhatsApp popup shows up to three recent messages
  from the same conversation, with the count and `Reply` / `Open` actions,
  instead of replacing the previous message.
- **Chat history survives logout (partial).** Chat messages are saved to
  `~/.local/share/perdana.island/messages.json` (mode 0600) and restored at the
  next login. See the known issues below.
- **Resting lyrics no longer freeze** until the island is opened. The media and
  resting-lyrics tickers recover from a failed frame, and a stuck close flag
  heals itself.
- **Prayer reminders match the v2 design.** The next-prayer highlight, card
  layout, and typography are restored. Tomorrow's Fajr is no longer highlighted
  as "next" for today.

## Changes

- Adds `extension/message-history.js`: merge, grouping, and persistence helpers
  with no GNOME imports, so the rules are unit-tested.
- Adds `extension/message-group.js`: the `MessageGroup` conversation card
  (`GObject.registerClass`, extends `St.BoxLayout`) with `open`, `mark-read`,
  `reply`, and `expanded-changed` signals.
- Messages page: scrollable list, `Mark all read` and `Clear` keep working. Mark
  read updates state without deleting history.
- Notification popup: burst of up to three messages per conversation; keyboard
  activation; seven-second hold; restarts on each new message.
- Reminders: v2 next-prayer tile, strip highlight limited to today's remaining
  prayers, `tomorrow` label after the last prayer.
- Resting island: ticker recovery and close-state self-healing.
- Accent colors: the St CSS engine does not resolve `var()`, so accent colors
  are applied through the inline pass. No `var()` remains in `stylesheet.css`.
- Packaging: `scripts/package-release.sh v79` includes the two new modules.
- Tests: 37 unit tests (the repository suite now includes message-history and
  persistence coverage).

## Known issues

- **Open does not work for restored messages.** A message restored after a
  restart has no live GNOME notification, and its saved app id is empty, so
  `Open` cannot find the WhatsApp PWA. Live messages still open normally.
- **Messages that arrive while logged out are not recovered.** WhatsApp Web
  only notifies while the PWA is running.
- **Restore after logout depends on the session.** It worked in the tested
  logout/login cycle. A diagnostic line (`Perdana Island restored N chat
  messages`) is written to the shell journal if a future cycle does not restore.
- **The last second of changes before logout may be lost** if GNOME Shell exits
  without disabling the extension. The save is debounced by 0.8 s.
- **Identical consecutive text** (for example `ok` sent twice) is merged into
  one row because GNOME gives no per-message timestamp for a reused
  notification object.
- **Message text is stored in plain text** on disk, readable only by your
  user. Clear removes it from the file.
- **Shexli** (static analysis) still crashes with SIGSEGV under Python 3.14
  on the development system. The result is inconclusive, not a pass.
- **Layout is not checked on every monitor width.** The popup and Messages
  layout was tuned on one display.

## Verification

- `scripts/validate.sh` passes (syntax, metadata, schemas).
- `npm test`: 37/37 pass.
- `scripts/package-release.sh v79` builds the archive; its metadata reports
  `v79` for GNOME Shell 50 and 51.
- Manual checks on a GNOME Shell session: the Messages scroll, bubble layout,
  and logout/login restore of unread messages were confirmed. The `Open`
  action for restored messages was not, and is listed as a known issue.

Cross-monitor movement (PR #17) is still deferred.
